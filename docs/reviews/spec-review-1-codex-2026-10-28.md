**No—the spec is not ready to plan and build against because its mask semantics, recipe execution, frame mappings, and interoperability contracts contain unresolved contradictions.**

1. **[blocker] Core weights contradict the required feather profile.** [Mask record, Renderings, Testing; ~213–259, 523–529](rascal/SPEC.md:213)  
   **Why:** The composite is “hard inside the core,” `core + blend` supplies paste weights, and the planes are disjoint—but the profile must have its “50% contour at the core’s edge.” A continuous CDF cannot simultaneously reach that boundary at 50% and remain full-weight throughout the core. Different implementations will produce different editable regions. Protect precedence also needs to govern prescriptions and subsequent refinements, not just rendering.  
   **Concrete change:** “Core and protect are binary planes. Core pixels have paste weight 1; blend contains fractional weights only outside core. The 50% contour lies within blend, not at the core boundary. Feather support is finite and versioned. Protect forces effective weight to zero for every rendering, prescription, refinement and paste; refinements preserve existing protection unless explicitly replaced.”

2. **[blocker] `cut` cannot satisfy its aspect parameter and lossless inverse as specified.** [Images and frames, Recipes, Testing; ~185–192, 309–312, 526–527](rascal/SPEC.md:185)  
   **Why:** Two full-height strips determine the canvas aspect. For a 2:1 panorama, strips each covering 7% of its width produce a canvas aspect of 0.28, not 9:16. Resizing breaks byte-exact inversion; cropping loses rows; padding needs an explicit mapping and invalid-pixel policy. None is chosen.  
   **Concrete change:** “In v1, `cut` performs no resampling, cropping or padding. For width W ≥ 2, it chooses integer strip width s, records the rounding rule, and concatenates the rightmost s columns followed by the leftmost s columns into a 2s × H canvas. The plan records both source spans. `put` copies those spans back exactly. Remove `aspect` from v1; reject unsupported image sizes.”

3. **[blocker] The recipe executor lacks a usable typed dataflow, and the seam recipe cannot create its required prescription.** [Mask record, Operations, Recipes; ~223–226, 274–346](rascal/SPEC.md:223)  
   **Why:** Default chaining passes the previous “mask or location,” but `cut` returns a frame and plan, `fan` returns an undefined standalone profile artifact, and `ramp` returns pixels. `ramp` requires an existing `tone_ramp` prescription; no operation creates one. The record says `prep` applies prescriptions, but there is no such operation or defined execution stage. Finally, `requires` has no semantics establishing whether a prerequisite actually succeeded on the relevant inputs.  
   **Concrete change:** “Each step has an id and explicit, typed input bindings such as `inputs.frame = 'cut.frame'`; outputs have named artifact types, including BandProfile. `ramp` estimates and stores a prescription and returns a mask. `heal` applies prescriptions exactly once to a working image before invoking the filler. Requirements are checked against successful, compatible bound outputs immediately before execution; skipped or failed prerequisites never satisfy them.”

4. **[blocker] The copied schemas cannot represent the promised public contract unchanged.** [Assumptions, Decisions, Locations, Operations, Schema tests; ~21–25, 99–101, 194–200, 266–270, 533–535](rascal/SPEC.md:194)  
   **Why:** Dejaview’s [location enum](dejaview/schemas/envelope-v1.json:119) excludes `line` and `stroke`, and its location objects reject additional properties. Its closed envelope has no defined field for mask records, profiles, prescriptions or artifact ids. Its image mappings support bbox or perspective-view mappings, not a piecewise cut canvas. The permitted schema directory also contains no standalone frame-registry schema to copy. “Every … location rascal emits validates against the copied schemas” is therefore false.  
   **Concrete change:** “Copied contracts remain unchanged and validate only the common compatibility subset. Rascal defines separately versioned location, frame, manifest and result schemas, including typed mask/profile artifacts. Extended records are not claimed to validate against the copied contracts. Interoperability outside the common subset requires an explicit adapter; unsupported conversions fail without approximating geometry. All schemas and references ship locally.”

5. **[blocker] The MCP server cannot yet be driven by the promised standard client.** [Decisions, Sessions, Success; ~99–101, 378–388, 580–581](rascal/SPEC.md:378)  
   **Why:** “`_harness` injected” does not identify the injector or object schema. A standard client has no specified way to import images, discover ids, or supply that context. Existing CLI commands also lack a defined workspace attachment mechanism. Separately, dejaview explicitly requires [`_dejaview` and `dejaview` manifest annotations](dejaview/SPEC.md:1026), so renaming the injected object does not plug together without translation.  
   **Concrete change:** “The public workspace server advertises ordinary arguments without `_harness`; it resolves ids and constructs internal context itself. Add workspace import, list and describe tools and a CLI `--workspace` option using the same registry. Specify the protocol revision, initialization, tool schemas, result serialization and error mapping. Pack context has a separately defined schema. Dejaview interoperability uses an explicit `_dejaview` adapter.”

6. **[blocker] The shipped remove and repair recipes require missing or deferred capabilities.** [Operations, Recipes, Commands, Success, Milestones; ~276–295, 349–351, 439, 574–575, 598–613](rascal/SPEC.md:349)  
   **Why:** Repair invokes “fan along the path,” expressly deferred until later. Remove passes a stroke into mask-only operations without a specified conversion. `shadow` appears in recipes and milestones but not the catalogue; the catalogue instead offers `grow --down`. The `fan` command writes `.mask`, although its declared output is a profile. Three recipes cannot meaningfully run on an arbitrary JPEG without the location inputs needed by remove and repair.  
   **Concrete change:** “V1 repair is `stroke → tighten → feather`; path fan is later. Add a defined location-to-mask rasterization operation for rectangle/stroke removal. Spell shadow growth as `grow --down` everywhere. `fan` writes a BandProfile consumed by `profile`. Ship three recipes plus the protect rendering profile. Installed recipes are addressable by built-in name; remove and repair require explicit location arguments, while requiring no configuration file.”

7. **[important] Paste preservation is measured against an ambiguous baseline.** [Images, Operations, Fillers, Success; ~175–176, 290–293, 370–374, 576–577](rascal/SPEC.md:370)  
   **Why:** The image supplied to paste may already contain the tone ramp. Equality to that frame does not establish equality to the original input, especially inside protect zones. RGB/RGBA blending, color space and alpha treatment are unspecified. “Byte-identical to the input” also needs to mean decoded samples, not JPEG file bytes.  
   **Concrete change:** “Retain immutable canonical pixels B before prescriptions. Paste initializes its output from B and writes only pixels with nonzero effective weight; protected and zero-weight pixels are copied without arithmetic. Feather computes the weighted composite in a named color/alpha convention; hard paste writes only unprotected core pixels. `heal` verifies preservation against B after mapping back to raw coordinates. Byte equality refers to canonical decoded channel samples.”

8. **[important] Automatically resizing arbitrary filler output can silently misregister the edit.** [Fillers; ~355–374](rascal/SPEC.md:355)  
   **Why:** A changed output size might represent a crop, padding, rotation or aspect change. Resizing it back and recording that action does not establish correspondence. `max_side` also does not say how the window is chosen, how masks are sampled, or how its transform is undone.  
   **Concrete change:** “Output dimensions must equal request dimensions by default; otherwise fail. An explicit resize policy may permit a known uniform scale with unchanged aspect and content extent. Rascal records the complete request transform, image and mask sampling policies, and inverse mapping before invocation. Paste always uses the original record’s weights in the original frame, never a resized rendering read back as a mask.”

9. **[important] Location mapping needs one-to-many results and explicit local topology.** [Images and frames, Testing; ~177–200, 527–528](rascal/SPEC.md:177)  
   **Why:** A location spanning the cut canvas’s center maps to two separated raw regions. A single bbox would include the panorama’s untouched middle. Seam rules cover only boxes and polygons, leaving crossing strokes and lines ambiguous. A cut/crop must not inherit full-panorama wrap behavior merely because its root is equirectangular. Clipped geometry cannot satisfy an unconditional round-trip identity test.  
   **Concrete change:** “Mapping returns `{parts, partial, source_location}` and may split geometry at discontinuities. Each frame declares its own pixel topology separately from its root projection. Only complete raw equirectangular frames wrap horizontally. Split seam-crossing lines and strokes while retaining their grouping. Define normalized pixel coordinates and brush-width units. Exact round trips apply only to unclipped, invertible mappings; clipped mappings retain the original geometry and report `partial`.”

10. **[important] The Poisson mode lacks the numerical problem that implementation and tests would solve.** [Decisions, Operations, Testing, Milestones; ~105–106, 293, 529, 601](rascal/SPEC.md:293)  
    **Why:** “Solves the gradient domain over `core + blend`” leaves source versus mixed gradients, soft weights, protected holes, image borders, wrap adjacency, color space, convergence and failure behavior open. A domain covering the entire image may have no fixed boundary and needs anchoring. An analytic test cannot establish correctness until these choices exist.  
    **Concrete change:** “Either defer Poisson beyond v1, or specify a discrete four-neighbor source-gradient solve over unprotected editable pixels, with immutable baseline values as Dirichlet conditions outside the domain and in protected holes. Define border topology, anchoring for boundary-free components, color space, soft-weight application, residual tolerance and iteration limit. Nonconvergence is an operational error, never an implicit feather fallback.”

11. **[important] The fan, Gaussian smoothing and tightening descriptions do not fix their algorithms sufficiently.** [Operations, Constants, Code style; ~280–298, 497–511](rascal/SPEC.md:280)  
    **Why:** Fan omits ruler windows, brightness normalization and units for `wide_max`; its “gate shut” formula still returns `thin`. Gaussian smoothing lacks support and endpoint behavior. “Path snapped to the strongest edges” does not distinguish the two boundaries of a scratch from its centerline, or establish continuity and tie handling. These are output-defining decisions, not Rust implementation details.  
    **Concrete change:** “Before M2/M4, add normative algorithm tables defining each ruler’s samples, color space, normalization, units and degenerate cases. A closed fan gate returns `thin` and is described as minimum-width, not zero-width. Row smoothing uses a normalized finite Gaussian kernel with specified truncation, boundary extension and rounding. Tighten searches for paired defect boundaries within the brush corridor, applies a stated continuity rule, and preserves the original stroke where no qualifying pair exists.”

12. **[important] Rendering profiles do not have an unambiguous consumer contract.** [Renderings, Fillers; ~250–262, 355–365](rascal/SPEC.md:250)  
    **Why:** `alpha` and `tinted` are modified source images, while the filler protocol always sends `image` and `mask`. It does not say which field receives them. `protect` calls itself an inverse but does not define whether white means editable or protected; inversion can also re-enable an existing protect zone unless protection is reapplied.  
    **Concrete change:** “Each profile declares its role, channel format, polarity and source frame. Grey and binary populate `mask`; alpha and tinted populate `image` and omit `mask` unless the filler contract explicitly requires both. For second-pass editing, protect outputs inverse edit weights with existing protect pixels forced back to zero. Rendered images carry an artifact type distinct from MaskRecord and are rejected by every mask-record input.”

13. **[important] Provenance is insufficient for replay, and byte determinism contradicts timestamps and durations.** [Principles, Mask record, Recipes; ~156–165, 211, 228–246, 338–340](rascal/SPEC.md:228)  
    **Why:** The example provenance has an op, version, selected parameters and duration, but no immutable input bindings or resolved defaults. Source location ids do not identify the source pixels needed by fan or tighten. The run-directory contents do not explicitly include all source bytes. Meanwhile `created` and `duration_ms` prevent identical output bytes across runs.  
    **Concrete change:** “A self-contained run stores canonical inputs, immutable intermediate artifacts and recorded external outputs. Every provenance node names input/output hashes and fully resolved parameters, algorithm, profile and constant-set versions. Replay reuses recorded external outputs. Deterministic equality covers pixels and canonical semantic metadata; timestamps and execution durations are journal observations excluded from content identity.”

14. **[important] A directory is not yet a concurrency or cancellation contract.** [Sessions, Testing; ~378–388, 538–541](rascal/SPEC.md:378)  
    **Why:** Concurrent tools, CLI invocations and server processes can overwrite registry files, reuse ids or expose half-written masks. Tombstoning a cancelled RPC response does not stop its worker from committing files. “Nothing … in memory … not also on disk” does not define recovery.  
    **Concrete change:** “All workspace writers use one shared locking and transaction protocol. Operations write immutable artifacts into private staging directories and publish registry changes only after successful validation. Cancellation before commit prohibits publication; committed operations remain committed. Persist id allocation and terminal operation state, and recover or discard incomplete transactions on startup. Readers see only committed artifacts.”

15. **[important] The MCP client’s credential and process rules are not executable contracts.** [Sessions; ~385–388](rascal/SPEC.md:385)  
    **Why:** “Anything shaped like a credential” cannot determine whether a declared variable is allowed, especially when a configured credential has an innocuous name. Concurrency precedence, deadline values, startup validation, result/image correspondence and process reuse after cancellation are also unstated. The sibling’s contract specifies these; copying its schema does not copy its behavior.  
    **Concrete change:** “Pack environments contain only named baseline variables and declared additions, minus every configured credential-source variable and names ending in `_KEY`, `_TOKEN` or `_SECRET`; rejection wins over explicit declaration. Define startup/call/shutdown deadlines and a pack concurrency limit, with serial execution unless permitted by the manifest. Validate initialization, complete tool listing, schemas, result bounds and image correspondence. Terminate a timed-out or cancelled pack before reuse, and redact all captured output.”

16. **[important] Several advertised measurements cannot be computed from their declared inputs.** [Operations, Measures, Commands; ~294, 390–394, 442](rascal/SPEC.md:294)  
    **Why:** Drift requires a before image, but `measure` takes only a frame/composite and a mask/line. Tone, chroma, hue and texture measures lack formulas and sampling domains. Per-row measurements also need row coordinates and serialization; the copied envelope’s measurement value is scalar.  
    **Concrete change:** “Change measurement inputs to explicit `before`, `after` and geometry bindings in the same frame; measures lacking required inputs return `not_applicable`. Version every measure’s formula, color space, window, normalization and empty-domain behavior. Store row series as typed artifacts with row coordinates and units, and return named scalar summaries in the envelope.”

17. **[important] The lab promises execution and resumption without defining either input or identity.** [Recipes, Lab; ~345–351, 398–404](rascal/SPEC.md:398)  
    **Why:** The lab uses fillers “where a recipe says,” but recipes have no filler field; only `heal` selects one. Matrix arms, spend declarations, resume keys and pick-file formats are absent. Resuming by directory existence could silently reuse outputs after changing images, constants or fillers.  
    **Concrete change:** “A versioned matrix defines named arms containing recipe, resolved overrides, optional filler and declared per-call spend. Cell identity hashes image bytes, recipe contents, resolved parameters, filler identity and relevant versions. Resume reuses only complete matching cells; rerunning an external call is explicit. Define versioned assignment and pick files, deterministic blind randomization, and exclusion of incomplete cells.”

18. **[important] The clean-room and model boundaries contradict authorized v1 work.** [Assumptions, Decisions, Boundaries, Open questions; ~14–24, 107–109, 566–568, 615–616](rascal/SPEC.md:14)  
    **Why:** “Nothing … is copied” conflicts with copied schemas. The unconditional ban on calling a vision model conflicts with invoking the segmenter pack and model-backed fillers. Sharing the sibling viewer’s template family also conflicts with the prohibition on copying code unless “sharing” means independently implementing a common data contract.  
    **Concrete change:** “The only copied repository material is the explicitly listed schema data with pinned provenance and required licensing notices. Rascal contains no model-driven controller or in-process inference; explicitly configured finder packs and fillers may run models. Viewer templates and fixtures are independently authored; any shared implementation requires a separately approved boundary change.”

19. **[important] Offline Python provisioning is an acceptance promise without a distribution contract.** [Decisions, Commands, Testing, Success, Open questions; ~107–109, 431–433, 548–550, 582–583, 608–609](rascal/SPEC.md:431)  
    **Why:** The bundle’s contents and supported platforms are undefined, and digest checks alone do not demonstrate offline installation. “The one step that may download” conflicts with explicit model fetching and network-enabled setup. The model’s export, prompt/click support and redistribution feasibility remain unresolved until the last pack milestone.  
    **Concrete change:** “Resolve segmenter export and redistribution feasibility before committing to M5’s acceptance scope. Define supported Python/platform combinations and a bundle containing the locked package artifacts, model artifacts and digests required for disconnected setup. Separate network-enabled fetch from strictly offline install and launch. Test installation and inference in a fresh disconnected environment. The pure-Rust dependency rule applies to the Rust binary; document the optional pack’s separate runtime requirements.”

20. **[important] The listed tests do not establish several success criteria, and the quality criterion has no decision rule.** [Testing, Success; ~521–553, 574–588](rascal/SPEC.md:521)  
    **Why:** A fake client can reproduce the server’s own protocol mistake; a deterministic blur filler does not test resizing or re-encoding; unit paste checks do not establish preservation through prep/window/put. No listed test proves fresh-install recipe discovery, disconnected bundle installation or documentation completeness. “Preferred,” “not worse” and “under three minutes” lack a scoring rule or execution baseline.  
    **Concrete change:** “Add release acceptance cases for fresh installation, an independently implemented MCP client, CLI/server workspace interchange, disconnected pack setup, malformed/mis-sized fillers, and full-pipeline preservation of protected and unmasked pixels. Check documentation coverage against the registry. Before viewing results, freeze corpus groups, arms, seeds, tie handling and the aggregate preference/non-regression rule. State the reference machine and whether the three-minute limit excludes compilation.”
